The important rule with Vercel AI SDK is simple:

> Let the model generate ToonUI, but let your app keep the chat state and side effects.

## Recommended pattern

Use `toon.messages.toUIMessage(payload)` to append structured user intent back into `useChat`-style state.

```tsx
onReply={(payload) => {
  const next = toon.messages.toUIMessage(payload);
  append(next);
}}
```

## Why this matters

This keeps three things separate:

- the model output
- the rendered interaction surface
- the app-owned message loop

## When to use `toModelMessage`

If your host loop expects a compact normalized user message for the next model turn, use:

```ts
const next = toon.messages.toModelMessage(payload);
```

That gives you:

- `content` for the model
- `displayContent` for UI
- the original typed `payload`

## Practical rule

- use `toUIMessage()` for UI state
- use `toModelMessage()` for LLM loop integration

## Helpers you still own in the host app

ToonUI already solves the typed interaction conversion layer:

- `toon.messages.toUIMessage(payload)`
- `toon.messages.toModelMessage(payload)`
- `toon.messages.toDisplayContent(payload)`
- `toon.prompt`

What ToonUI does **not** do for you is inspect arbitrary AI SDK `UIMessage` history objects from your app state.

That means helpers like these still belong in the host app:

```ts
import type { UIMessage } from 'ai';

export function getMessageTextContent(message: UIMessage) {
  return message.parts
    .filter((part) => part.type === 'text')
    .map((part) => part.text?.trim() ?? '')
    .filter(Boolean)
    .join('\n\n');
}

export function getMessageDisplayContent(message: UIMessage) {
  if (
    message.role === 'user' &&
    message.metadata &&
    typeof message.metadata === 'object' &&
    'displayContent' in message.metadata &&
    typeof message.metadata.displayContent === 'string' &&
    message.metadata.displayContent.trim()
  ) {
    return message.metadata.displayContent.trim();
  }

  return getMessageTextContent(message);
}

export function prependToonProtocolPrompt(
  systemPrompt: string,
  toonProtocolPrompt: string,
) {
  return [toonProtocolPrompt, systemPrompt].join('\n\n');
}
```

## What ToonUI already resolves vs what you still compose

| Need | Resolved by ToonUI? | How |
|------|----------------------|-----|
| Typed reply payload | Yes | `toon.events.reply()` / UI handlers |
| Typed submit payload | Yes | `toon.events.submit()` / UI handlers |
| Convert payload to UI message | Yes | `toon.messages.toUIMessage()` |
| Convert payload to model message | Yes | `toon.messages.toModelMessage()` |
| Human display label from a ToonUI payload | Yes | `toon.messages.toDisplayContent()` |
| Canonical ToonUI system prompt | Yes | `toon.prompt` |
| Read plain text from any arbitrary AI SDK `UIMessage` | No | host helper |
| Prefer `metadata.displayContent` when rendering stored user messages | No | host helper |
| Combine your app system prompt with ToonUI protocol prompt | No | host helper |

## Recommended composition

Use this mental model:

- ToonUI owns the **protocol**
- your app owns the **message history**
- AI SDK owns the **transport and message loop**

So the right composition is:

```ts
const system = prependToonProtocolPrompt(systemPrompt, toon.prompt);
```

And for rendering stored messages:

- use `getMessageDisplayContent(message)` for user bubbles
- use `getMessageTextContent(message)` when you need raw text extraction
