ToonUI lets a model answer with normal markdown plus fenced `toon-ui` blocks.

The important architectural rule is this:

> The model describes **UI intent**, but your application still owns business logic, tools, transport, persistence, auth, and safety boundaries.

That separation is the whole point.

## What problem ToonUI solves

Most AI UI demos mix three different concerns into one fragile layer:

1. prompt instructions
2. rendering primitives
3. application behavior

That usually creates hidden coupling:

- prompts start carrying business logic they should not own
- frontend rendering becomes tied to one demo implementation
- user actions are hard to convert back into structured app events

ToonUI separates those concerns into explicit packages and APIs.

## What ToonUI is made of

| Package | Responsibility | Use it when |
|---|---|---|
| `@toon-ui/core` | Protocol, catalog, parser, validation, prompts, events, messages | You need the server-side contract |
| `@toon-ui/react` | Explicit React runtime and adapter layer | You want to control rendering ownership |
| `@toon-ui/toon-ui` | Main public client package with default adapter | You want the fastest path |
| `@toon-ui/prompts` | Prompt helpers only | You want custom prompt composition |
| `@toon-ui/cli` | Validation and AST inspection in the terminal | You want CI or debugging support |

## Quick path

1. Create a protocol on the server with `createToonProtocol()`.
2. Inject `toon.prompt` into your system prompt.
3. Create a client runtime with `createToonClient()` or `createToonReactRuntime()`.
4. Render assistant output with `ToonMessage` or `ToonRenderer`.
5. Reinject user interactions with `toon.messages.toUIMessage(payload)` or `toon.messages.toModelMessage(payload)`.

## End-to-end mental model

Think about ToonUI as a pipeline:

1. **Rules**: your server teaches the model the language
2. **Output**: the model emits markdown plus `toon-ui` blocks
3. **Parsing**: ToonUI extracts and parses those blocks
4. **Validation**: the AST is checked against the official catalog
5. **Rendering**: React components render the structured nodes
6. **Interaction**: button clicks and form submits become typed payloads
7. **Reinjection**: those payloads go back into your chat/application loop

## What ToonUI owns vs what your app owns

| ToonUI owns | Your app owns |
|---|---|
| UI language | Tools and side effects |
| Parser and validator | Auth and permissions |
| Prompt composition helpers | Persistence |
| Rendering runtime | API calls |
| Event/message conversion | Business rules |
| Adapter contract | Final product decisions |
