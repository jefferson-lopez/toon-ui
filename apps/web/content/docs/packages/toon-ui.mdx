`@toon-ui/toon-ui` is the main public client package.

Use it when you want the easiest path:

- default adapter included
- clean naming
- access to the protocol and React runtime through one package

## Main exports

- `createToonClient()`
- `createToonAdapter()`
- `ToonMessage`
- `ToonRenderer`
- `extractToonMarkdown`
- all public exports from `@toon-ui/core`
- all public exports from `@toon-ui/react`

## Main exports explained

This is the part that usually gets documented badly, so let's make it explicit.

### `createToonClient()`

This is the main convenience entrypoint.

```tsx
import { createToonClient } from '@toon-ui/toon-ui';

const toon = createToonClient();
```

What it does:

- creates a React runtime
- uses a default adapter automatically if you do not pass one
- gives you access to protocol APIs, parsing, validation, rendering, and interaction helpers through one runtime object

What it is really wrapping:

- `createToonReactAdapter({ level: 'default' })`
- `createToonReactRuntime(...)`

Use it when:

- you want the fastest correct setup
- you do not want to wire `@toon-ui/react` manually yet

### `createToonAdapter()`

This is an alias for the React adapter factory.

```tsx
import { createToonAdapter } from '@toon-ui/toon-ui';

const adapter = createToonAdapter({
  level: 'default',
  components: {
    button: MyButton,
  },
});
```

Use it when:

- you are using `@toon-ui/toon-ui`
- but still want to customize selected UI components

Important detail:

- in `@toon-ui/toon-ui`, `createToonAdapter()` is just a cleaner public alias over `createToonReactAdapter()`

### `ToonMessage`

High-level rendering component for mixed assistant content.

```tsx
<ToonMessage
  content={assistantContent}
  runtime={toon}
  onReply={(payload) => append(toon.messages.toUIMessage(payload))}
  onSubmit={(payload) => append(toon.messages.toUIMessage(payload))}
/>
```

What it does:

- extracts markdown from the response
- extracts `toon-ui` blocks
- renders normal markdown
- renders the structured ToonUI block
- wires reply and submit interactions

Use it when:

- your model returns normal prose plus UI blocks in the same message
- you want the best default experience

### `ToonRenderer`

Lower-level rendering component focused on the structured block.

Use it when:

- you want more control than `ToonMessage`
- you already know where the structured content should render
- you want to separate prose rendering from ToonUI rendering

### `extractToonMarkdown`

Utility that removes fenced `toon-ui` blocks from mixed content and leaves the normal markdown.

```tsx
import { extractToonMarkdown } from '@toon-ui/toon-ui';

const markdown = extractToonMarkdown(content);
```

Use it when:

- you want to render prose and structured UI in different places
- you want custom markdown rendering

### All public exports from `@toon-ui/core`

This package re-exports the full public core surface.

That means you can also access, from `@toon-ui/toon-ui`:

- `createToonProtocol()`
- `parseToonUI()`
- `validateToonUI()`
- `extractToonBlocks()`
- `createPrompt()`
- `createRules()`
- all public types

Why this matters:

- `@toon-ui/toon-ui` acts as an umbrella client entrypoint
- many apps can import most of what they need from one package

### All public exports from `@toon-ui/react`

This package also re-exports the React surface.

That means you can also access:

- `createToonReactAdapter()`
- `createToonReactRuntime()`
- `getToonButtonProps()`
- `getToonInputProps()`
- hooks like `useToonAction()`
- component and adapter types

Use this when you want:

- the convenience of one package
- but still need lower-level React control later

## Practical decision rule

Use:

- `createToonClient()` if you want the easiest path
- `createToonAdapter()` if you need light customization
- `ToonMessage` if the model response mixes prose + ToonUI
- `ToonRenderer` if you want lower-level rendering control
- `extractToonMarkdown()` if you want to split prose from ToonUI yourself

## Happy path

```tsx
'use client';

import { ToonMessage, createToonClient } from '@toon-ui/toon-ui';

const toon = createToonClient();

export function AssistantMessage({
  content,
  append,
}: {
  content: string;
  append: (message: unknown) => void;
}) {
  return (
    <ToonMessage
      content={content}
      runtime={toon}
      onReply={(payload) => append(toon.messages.toUIMessage(payload))}
      onSubmit={(payload) => append(toon.messages.toUIMessage(payload))}
    />
  );
}
```

## Partial customization

The runtime keeps the resolved adapter on `toon.adapter`, so you can inspect what actually got registered.

```tsx
import {
  createToonAdapter,
  createToonClient,
  getToonButtonProps,
  type ToonButtonComponentProps,
} from '@toon-ui/toon-ui';

function MyButton(props: ToonButtonComponentProps) {
  return <button {...getToonButtonProps(props)}>{props.node.label}</button>;
}

const adapter = createToonAdapter({
  level: 'default',
  components: {
    button: MyButton,
  },
});

const toon = createToonClient({ adapter });
```

## When to use this package

Use `@toon-ui/toon-ui` when:

- you want the default adapter
- you want to override only a few components
- you want the cleanest public entry point

Use `@toon-ui/react` when:

- you want explicit adapter ownership
- you are integrating a real design system
- you want tighter control over registration coverage
